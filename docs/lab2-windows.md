# ЛР2: простий запуск на своєму Windows ПК

Цей крок доповнює вже виконані тести в GitHub Actions. Потрібен для вимоги методички: API, PostgreSQL і k6 на одному **фізичному ПК без Docker, VM та WSL**. Автоматичний launcher не доводить відсутність VM: перед запуском це підтверджує користувач. Дані CI не підставляються у локальні результати.

## 1. Один раз установити програми

- **Node.js 24 LTS:** [офіційний Windows installer](https://nodejs.org/en/download). Якщо пропонується інша основна версія, вибрати 24 LTS. Додаткові build tools для цього проєкту не потрібні.
- **PostgreSQL 16:** [офіційна сторінка Windows](https://www.postgresql.org/download/windows/), кнопка Download the installer. Установити PostgreSQL Server, залишити порт 5432 та запам’ятати пароль користувача `postgres`. StackBuilder і додаткові пакети для лабораторної не потрібні. Уже встановлений нативний PostgreSQL 16 можна використати.
- **k6 1.3.0:** [офіційний release](https://github.com/grafana/k6/releases/tag/v1.3.0). Завантажити `k6-v1.3.0-windows-amd64.zip`, розпакувати й покласти **сам файл `k6.exe`** у папку `tools` в корені проєкту. Папку `tools` створити, якщо її немає. Встановлений k6 із PATH теж підтримується; його фактична версія записується в результати.

Нічого платного, облікового запису Grafana чи хмарного PostgreSQL не потрібно. Після встановлення Node відкрити новий термінал.

## 2. Завантажити код саме гілки ЛР2

[ZIP гілки lab2-k6](https://github.com/mishasamonov/traveler-api-dds-lab1/archive/refs/heads/lab2-k6.zip).

Розпакувати. Відкрити папку, де знаходиться `package.json`, і через адресний рядок Провідника запустити `powershell`. Git встановлювати необов’язково.

Альтернатива, якщо Git уже є:

```powershell
git clone --branch lab2-k6 https://github.com/mishasamonov/traveler-api-dds-lab1.git
cd traveler-api-dds-lab1
```

## 3. Запустити

Спочатку встановити залежності й перевірити Node/k6:

```powershell
npm.cmd ci
npm.cmd run lab2:check
```

`--check` не створює БД і не запускає тестів; це лише перевірка доступності програм.

Потім повний цикл:

```powershell
npm.cmd run lab2:local
```

Підтвердити `так`, якщо це дійсно фізичний ПК без віртуалізації. На першому запуску:

1. Натиснути Enter для порту `5432`.
2. Натиснути Enter для користувача `postgres`.
3. Ввести пароль, заданий при встановленні PostgreSQL, і натиснути Enter. Символи не показуються — це нормально.

Launcher створить нову окрему БД `traveler_lab2_…` і новий обмежений обліковий запис. БД та облікові записи ЛР1 не змінюються. Пароль адміністратора не записується у файли. Згенерований пароль окремого облікового запису залишається тільки в приватному локальному `.lab2-local/database.json`, який виключений із Git. **Цю папку не надсилати та не публікувати.**

Після цього API автоматично запускається на `127.0.0.1:4567`, застосовується схема й послідовно виконуються Smoke, Load, Stress, Spike, Endurance. Додатковий Stress до 8000 VU не входить до цього стандартного циклу. API зупиняється після завершення, тестова БД залишається для повторних запусків.

Повний цикл займає приблизно **40 хвилин** залежно від продуктивності ПК; сам Endurance — 30 хв. На цей час під’єднати ноутбук до живлення, заборонити автоматичний сон і закрити важкі програми. Не зменшувати час Endurance заради швидшого завершення.

Якщо хочеться спочатку перевірити лише Smoke:

```powershell
npm.cmd run lab2:smoke
```

Це НЕ замінює повний цикл. Після успішного Smoke виконати `npm.cmd run lab2:local`.

## 4. Що надіслати для завершення звіту

У `tests/performance-tests/reports/` з’явиться нова папка `local-ДАТА…`:

- п’ять `*-summary.json` із фактичними метриками;
- п’ять `*-dashboard.html` із самодостатніми графіками;
- журнали k6 та API;
- `environment.json` із версіями, моделлю CPU і RAM, без пароля та імені комп’ютера;
- `exit-codes.txt`;
- `local-results.json` і `local-results.csv` зі зведеними цифрами.

Зробити скріншот фінальної таблиці в терміналі. Стиснути **тільки папку `local-…`** у ZIP і надіслати разом зі скріншотом. На її основі у Word-звіті буде додано справжній фізичний baseline. Поточні цифри CI не можна просто перейменувати на результати ПК.

## Якщо з’явилася помилка

- `Не знайдено k6`: перевірити, що це `tools/k6.exe`, не вкладена папка з архіву. Або установити k6 у PATH і заново відкрити термінал.
- `npm` блокується PowerShell: використовувати саме `npm.cmd`, як у прикладах. Змінювати системну execution policy не потрібно.
- `password authentication failed`: перевірити пароль саме користувача `postgres` PostgreSQL, а не пароль Windows.
- `ECONNREFUSED`: нативна служба PostgreSQL не запущена або вказаний інший порт.
- Порт `4567` зайнятий: закрити раніше запущений TravelerAPI. Launcher не зупиняє сторонні процеси.
- Код `99` у Stress/Spike: зафіксовано перевищення порогу продуктивності, це очікуваний результат пошуку межі; цикл продовжується. Для Load/Endurance таке перевищення означає непройдений критерій і теж має бути описане, а не приховане.
- `Ctrl+C`: запуск перервано, збережені файли можуть бути частковими. Повторити повний цикл; кожен запуск має окрему папку й не перезаписує попередні результати.

Якщо ОС інша, ті самі Node-команди працюють у нативному Linux/macOS з Node 24, PostgreSQL 16 і k6. У Linux/macOS замість `npm.cmd` використовувати `npm`. Відсутність Docker/VM лишається вимогою, а не властивістю launcher.

Офіційні довідки: [k6 installation](https://grafana.com/docs/k6/latest/set-up/install-k6/), [HTML dashboard export](https://grafana.com/docs/k6/latest/results-output/web-dashboard/), [PostgreSQL Windows installers](https://www.postgresql.org/download/windows/).
